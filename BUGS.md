## v75 — "records you can open" (Oct 14, shipped)
- FIXED (Revenue): the period chart's bars are tappable (each bar opens its day), and the main 📒 Entries / ✨ Extras rows open their day too (a tap on a row's own Delete button still only deletes). Day Details now EDIT as well as view/delete: every entry and extra gets ✏️ Edit → a prefilled form at the top of the detail (type, amount, hours/loads/miles/tonnes/trips, note) → Save changes writes VERIFIED (read-back byte-compare, v48 rule) — a failed write shows a plain in-page error, keeps the typed edit in the reopened form (dayEditDraft), and changes nothing. Day-detail deletes are verified the same way. While an edit is open, other rows render no Delete buttons (a delete would shift the indexes the edit points at). Entries/extras keep every field the form doesn't own (date, auto, photo…).
- FIXED (Fuel): Fill-ups rows are tappable → the form opens in EDIT mode prefilled (date, odometer, litres, cost, station; receipt photo shown when the record carries one; fields marked touched so OCR can't rewrite them), "💾 Save changes" updates the SAME entry in place (no duplicate), verified the same read-back way; Cancel edit is a quiet ghost. The add path is verified now too.
- FIXED (Fuel guard): a fill with BOTH litres and cost empty (or zero/non-numeric) can no longer save — new or edited. Blocked with a plain in-form message ("Enter the litres or the cost — a fill-up with neither can't be saved.") and the form is NOT re-rendered, so nothing typed is lost. The existing blank Oct 13 entry on the phone can now be fixed by tapping it and filling it in.
- FIXED (Dispatch): Edit now brings the form to the user — dspScrollToForm scrolls to the form card immediately, on the next frame, and once more at +350 ms (the old one-shot scrollIntoView did not survive the phone's late layout: ingest paint + ticket-photo decode). The tapped History item is also marked at the tap point (orange frame, "✏️ You're editing this one — the form is at the top of this page ↑", button reads "✏️ Editing ↑").
- FIXED (Manifest "Invalid Date"): ROOT CAUSE PROVEN from code — app.js stores session endedAt as an ISO STRING (toISOString), but collect() computed the start as `endedAt - seconds*1000` on the raw value → NaN → new Date(NaN) renders literally "Invalid Date", for EVERY saved session. (The older test fixtures used numeric endedAt, which is why the suites never saw it.) collect() now parses every stamp to ms first (stampMs/fmtStamp/fmtStartOf); unparseable values render "—", never "Invalid Date". Display only — start is still endedAt − seconds, end is still endedAt.
